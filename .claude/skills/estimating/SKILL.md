# Смета

## Две сметы
1. **Вилка (стадия 00)** — по брифу: мин/макс по аналогам, с явными допущениями.
2. **Точная (стадия 05)** — по раскадровке и шот-листу, построчно.

## Расчёт (как в «Смете PRO» владельца)
Строка = Кол-во × Смен × Цена × Коэф. → Прямые затраты →
+ непредвиденные (`markup.contingency_pct`) → + комиссия (`commission_pct`,
база `commission_base`) → подитог → − скидка → + налог (`tax_mode: gross` —
ИТОГ = подитог / (1 − налог)). Все проценты — из `studio/rates.yaml → markup`;
управление проектом и резерв отдельными строками НЕ добавляются — они уже
в непредвиденных и комиссии.

Источник цен по типу: `day_rate` (за смену по ролям), `per_project` (вилки за
проект — выбирай по сложности и объясняй выбор), `per_unit`, `onsite`, `shoot`.
Роль с `null` — в смету не ставим цену, а пишем вопрос владельцу.

## Структура `05_plan/estimate.md` / `estimate.csv`
`статья, роль, единица, кол-во, ставка, сумма, комментарий`
Разделы: препродакшен (стратегия, концепт, стиль, раскадровка) · продакшен
(моушн, 3D, композ — по шотам и сложности) · пост (монтаж, цвет, звук, диктор)
· технологии (рендер, нарезка, прогон на площадке) · лицензии (музыка, шрифты,
стоки) · управление проектом (10–15%) · резерв на риски (10–20%).

## Оценка трудозатрат
- Шот оценивается по сложности 1–5 × длительность; база — фактические данные
  прошлых проектов (`studio/rates.yaml` — ставки и нормы студии, ведёт владелец).
- Шаблонные серии: мастер (как уникальный шот) + N × время на версию + QC.
- Рендер: сек/кадр из теста × кадры × версии → часы машин.
- Нет данных для оценки — так и пишем, даём вилку и что её сузит.

## Условия (в КП)
Что входит / не входит; 2 круга правок на этап (сверх — допработа по ставке);
правка, возвращающая на прошлую стадию, — переоценка; этапы оплаты
(напр. 50/50 или 30/40/30); сроки зависят от сроков согласований клиента.

Ставки и цены — только из `studio/rates.yaml`; если файла нет — спроси владельца,
не придумывай рынок.
