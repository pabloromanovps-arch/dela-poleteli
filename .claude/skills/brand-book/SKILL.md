# Брендбук

Бренд живёт в `brands/<client>/` и подключается к проекту строкой
`brand: <client>` в `project.yaml`. Все цвета, шрифты и правила дизайн-библии
проекта берутся из `brand.yaml`, а не подбираются «на глаз».

## A. Разбор брендбука клиента
1. `python tools/new_brand.py <client>` — копия `brands/_template/`.
2. Исходники кладём в `brands/<client>/source/` (PDF брендбука, логотипы, шрифты).
3. Читаем брендбук целиком (PDF — постранично) и заполняем `brand.yaml`:
   - **colors**: каждый цвет с ролью (primary/secondary/accent/bg/text), HEX,
     при наличии RGB/CMYK/Pantone — как в брендбуке, без пересчёта «на глаз».
     Запиши пропорции, если указаны.
   - **fonts**: гарнитуры, начертания, где какая, файлы и **лицензия** (можно ли
     использовать в видео/на экранах). Нет кириллицы — фиксируем замену,
     указанную брендом, или вопрос клиенту.
   - **logos**: версии (основной, горизонтальный, знак, моно, инверсия), файлы
     (вектор!), охранное поле, минимальный размер, допустимые фоны.
   - **rules / donts**: всё, что запрещено (растягивать, менять цвет, тени,
     градиенты на логотипе, сочетания цветов).
   - **imagery / graphics**: фирменные элементы, паттерны, фото-стиль.
   - **motion**: если в брендбуке есть моушн-гайд — характер, кривые, тайминги,
     анимация логотипа. Если нет — помечаем `motion.source: derived` и
     выводим из характера бренда (см. C), согласуем с клиентом.
4. Всё, чего нет в брендбуке, → `open_questions` (не придумываем).
5. Контрольный лист: `python tools/brand_sheet.py <client>` → PNG с палитрой,
   шрифтами, логотипами. Смотрим его (Read) и сверяем с брендбуком.

## B. Применение бренда к экранам и моушну
- Брендбуки пишут для печати и веба. Для LED проверяем: насыщенные фирменные
  цвета на экране «кричат» — допускается экранная версия цвета, но только
  согласованная и записанная в `colors.<x>.screen`.
- Охранное поле и минимальный размер логотипа пересчитываем на дистанцию
  зрителя (`design-foundations`).
- В AE бренд доступен скриптам: `--args brand=<client>` → `DP.brand()`.
  Цвета — в `CTRL_color` (по ролям), логотипы — импорт из `brands/<client>/logos/`.
- Проверка соответствия на стадии 07: чек-лист ниже.

### Чек-лист бренда
□ только цвета бренда (по ролям и пропорциям) □ шрифты бренда, лицензия
есть □ логотип — оригинальный вектор, не перерисован, не перекрашен вне правил
□ охранное поле и минимальный размер □ ничего из `donts` □ фирменные элементы
используются по правилам □ моушн согласуется с `motion`

## C. Создание брендбука / моушн-айдентики с нуля
Стадии те же, что у проекта (бриф → референсы → концепт → стиль), результат:
1. Платформа: суть бренда, характер (3–5 слов), тон.
2. Логотип: версии, охранное поле, минимальные размеры, запреты.
3. Цвет: палитра по ролям + пропорции + доступность (контраст) + экранные версии.
4. Типографика: гарнитуры, иерархия, правила набора, кириллица.
5. Графика: фирменные элементы, сетка, паттерны, иконки, фото-стиль.
6. **Моушн-айдентика**: характер движения → пресеты кривых (`motion-language`),
   тайминги, анимация логотипа (интро/аутро/луп), переходы, звуковой логотип.
7. Носители: экраны (LED, 16:9, ультраширокие), соцсети, презентации, печать.
Брендбук верстается как презентация (`presentation-design`) → PPTX + PDF,
и параллельно рождается `brand.yaml`, чтобы бренд сразу работал в пайплайне.
