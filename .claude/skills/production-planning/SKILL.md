# Планирование производства

## Бриф (стадия 00)
Заполни `00_brief/brief.md`. Обязательные поля — без них ворота 00 закрыты:
- Цель: что зритель должен почувствовать/понять/сделать.
- Площадка и экран → профиль `screens/…`. Дистанция зрителя, свет в зале.
- Хронометраж, луп или линейный, синхрон с ведущим/музыкой/светом.
- Контент: тексты, логотипы, данные (таблицы!), фото, видео — что есть, чего нет.
- Ограничения: бренд-бук, запреты, юридическое (лицензии шрифтов и музыки).
- Сдача: формат, кодек, нарезка, медиасервер, дедлайн, этапы показа.
- Открытые вопросы — списком, каждый адресован клиенту или площадке.

## Декомпозиция (стадия 05)
1. Разбей ролик на **сцены → шоты**. Шот — отрезок с одной камерой/композицией.
2. Заполни `05_plan/shotlist.csv`:
   `shot_id,scene,start_tc,dur_s,description,tool,source_spec,data,depends_on,render_est_min,owner,status`
   - `tool`: ae / blender / c4d / ue / premiere / comp.
   - `data`: таблица, если шот из шаблона (тогда один шот = N версий).
3. Порядок сборки в `plan.md`:
   1) общие ассеты (логотипы, шрифты, материалы, риги, бит-сетка);
   2) шаблонные шоты (один мастер → проверка на крайних данных → пакет);
   3) уникальные hero-шоты (самые рискованные — раньше);
   4) композ и сборка мастера; 5) нарезка и сдача.
4. Риски: для каждого — вероятность, последствие, план Б (упростить шот,
   real-time вместо offline, предрендер фона).
5. Рендер-бюджет: тестовый кадр → сек/кадр × кадры × версии. Если не влезает
   в срок — решение принимаем сейчас, а не в ночь перед сдачей.

## Правки
`revisions/rNN.md`: дата, источник, список правок (шот, таймкод, что, почему),
к какой стадии относится, оценка, статус. Правка, меняющая концепт/стиль,
возвращает проект на 02/03 — сообщи об этом явно.

## Отчёт о статусе (всегда одинаковый)
Стадия · Готово · Ждёт решения (от кого) · Риски · Следующий шаг.
